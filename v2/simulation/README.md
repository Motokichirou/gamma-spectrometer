# v2/simulation — Монте-Карло разделения наложенных импульсов

Два стенда под две ветки входа. Отвечают на вопрос, задающий требования к АЦП,
предусилителю и ПЛИС: **при какой частоте выборки миллион импульсов в секунду
с NaI(Tl) ещё обрабатывается и какой ценой по разрешению и светимости.**

```
python v2/simulation/mc_pileup.py [--quick]              # ветка TIA: канал = амплитуда импульса
python v2/simulation/mc_csp.py    [--quick] [--no-refine] # ветка ЗЧУ: канал = высота ступеньки
```

Результаты в `out/*.json`. Выводы — в `../design.md` §6, решения — в `../decisions.md`.

## Чем отличается от стенда v1

`../../simulation/fix_c320/mc.py` — стенд **v1**: 4 Мвыб/с, ядро аналогового шейпера
CR-RC², загрузки до 30 кимп/с, проверка параболы против эталона. Под миллион он не
годится — в v2 аналогового шейпера нет вообще. Переиспользован только **реальный спектр
Cs-137** из обратной CDF в `firmware/core/pulsegen.c`.

## Общее в моделях

```
анод      i(t) = (Q/td)·exp(-t/td),  td = 230 нс — высвечивание NaI(Tl)
усилитель однополюсный, полоса f = fs/2.5 (сам работает противоалиасинговым фильтром)
шум       белый, ограничен полюсом усилителя
поток     пуассоновский, амплитуды из реального спектра Cs-137
метрика   робастная σ относительной ошибки амплитуды на фотопике -> вклад в FWHM;
          светимость = доля событий фотопика, дошедших до спектра
```

⚠ **Почему полоса привязана к `fs`.** Аналогового шейпера нет, значит усилитель сам
противоалиасинговый фильтр ⇒ `f ≤ fs/2` обязательно. Снизу полосу ограничивает точность
момента (`σ_t ~ e_n/(A·√f)`), то есть оптимум прижат к Найквисту. Рабочее значение 2.5.

---

## `mc_pileup.py` — ветка TIA (импульс)

Сигнал: `v(t) ~ exp(-t/td) - exp(-t/ta)`. АЦП 14 бит на 2.5 В.

Обработка: полюс-нуль `s[n] = y[n] − d·y[n−1]` (снимает спад 230 нс) → короткий бокскар
→ локальные максимумы + парабола → МНК по эталонам блоками с полями → трапеция
Jordanov–Knoll для сравнения.

| fs, Мвыб/с | 300 кимп/с | 1 Мимп/с | светимость @1М | трапеция одна @1М |
|---|---|---|---|---|
| 40 | 7.30 ± 0.14 % | 13.31 ± 1.56 % | 93.8 % | 99 % |
| 65 | 4.70 ± 0.17 % | 7.82 ± 0.65 % | 96.0 % | 97 % |
| **125** | **2.52 ± 0.05 %** | **4.08 ± 0.29 %** | **97.9 %** | 97 % |

(5 зёрен, 4 мс записи.) С собственными 7 % кристалла полное FWHM при миллионе —
**15.0 / 10.5 / 8.1 %**.

## `mc_csp.py` — ветка ЗЧУ со сбросом (ступенька), выбранная

Сигнал: монотонная лестница без спада,
`h(t) = 1 − (td·e^(−t/td) − ta·e^(−t/ta))/(td − ta)`, фронт 90 % за 2.3·td ≈ 530 нс.
`Cf` = 100 пФ, шаг 72 мВ на фотопике Cs-137, АЦП **16 бит** на 4.4 В, сброс при
заполнении рампы 4 В с окном 1 мкс.

Обработка: разность (лестница → импульс) → полюс-нуль (импульс → узкий пик) → бокскар
→ группировка пиков → кластерный МНК по ступенчатым эталонам + Левенберг-Марквардт
по моментам → разность двух средних для сравнения.

| fs, Мвыб/с | 100 кимп/с | 300 кимп/с | 1 Мимп/с | светимость @1М | 2 средних @1М |
|---|---|---|---|---|---|
| 40 | 2.56 % | 8.99 % | 32.22 % | 84.4 % | 185 % |
| 65 | 2.81 % | 5.25 % | 15.80 % | 85.6 % | 145 % |
| **125** | **1.01 %** | **3.82 %** | **12.46 %** | **91.7 %** | 122 % |

Мёртвое время на сбросы 0.90 % при миллионе — расчёт обещал 0.71 %, сошлось.

⚠ При 100 кимп/с и 125 Мвыб/с простая **разность двух средних даёт 0.14 %** — лучше
кластерного фита (1.01 %). На изолированных событиях фит лишний ⇒ в приборе нужны оба
измерителя с переключением по признаку наложения.

## Что из этого твёрдо в обеих ветках

- **штатные измерители при миллионе разваливаются полностью**: трапеция 97 %, разность
  двух средних 122 % FWHM. Разделение наложений обязательно при любой частоте выборки;
- **кластерный МНК сохраняет 92–98 % светимости** при миллионе — события разделяются,
  а не выбрасываются. Отбраковка вместо разделения оставляет 17–22 % света;
- **частота выборки — доминирующий рычаг**, FWHM масштабируется почти как `1/fs`;
- 20 Мвыб/с из прежнего ТЗ (AD4084) не годится ни в одной ветке.

## ⚠ Открытые места

1. **Моменты прихода не уточняются.** Именно это ограничивает точность: признак —
   масштабирование `1/fs`, то есть ошибка ограничена моментом, а не шумом.
   Левенберг-Марквардт с откатом реализован в `mc_csp.py` — и **прогон с ним и без него
   даёт бит в бит одинаковые числа**, то есть шаг отклоняется всегда. Защита работает
   (хуже не делает), выигрыша нет. Неукрощённый Гаусс-Ньютон в импульсной модели делал
   заметно хуже: 4.5 % → 7.1 %. См. `../decisions.md` D11.
2. **Систематики в моделях нет вообще** — ни температурного плывуна τ_d, ни зависящего
   от загрузки хвоста, ни баллистического дефицита. А это ровно то, ради чего выбиралась
   ветка ЗЧУ, и ровно то, из-за чего ветка TIA в симуляции выглядит лучше, чем будет
   в железе. См. `../decisions.md` D8.
3. **Эффекты ФЭУ при высокой загрузке не моделируются**: объёмный заряд на последних
   динодах, послеимпульсы, время восстановления усиления. Это измеряется на v1
   (`../measurements_v1.md`), а не считается.
4. Часть событий континуума **ниже порога обнаружения**: они невидимы, но в сигнале
   присутствуют и поднимают пьедестал. В модели учтено (спектр реальный), отдельно
   не исследовано.

## Четыре грабли, проверенные на этих стендах

Стоят того, чтобы не повторять — каждая давала физически бессмысленный результат:

1. ⛔ **Нельзя деконволюировать спад полностью и снимать момент с получившегося пика.**
   Его ширина становится `ta`: при 20 Мвыб/с это 0.16 отсчёта. Первая версия стенда
   давала из-за этого 15 % FWHM там, где должно быть меньше процента.
2. ⛔ **Согласованный фильтр для обнаружения при высокой загрузке — худший выбор.**
   Оптимален для одиночного импульса в шуме, но усредняет по всей длине эталона
   (20·td = 4.6 мкс) и при миллионе нашёл **537 событий из 1977**, а на моноэнергетическом
   источнике 45 из 1992. Детектор должен обострять, а не сглаживать.
3. ⛔ **Пара эталонов недостаточна.** При окне 4·td и миллионе в окне ~0.9 соседа,
   у ~24 % событий сосед не один. Нужно решать кластер целиком.
4. ⛔ **Недодизеренный АЦП ломает детектор.** При 14 битах на 4.4 В аналоговый шум
   (28 мкВ) настолько ниже LSB (269 мкВ), что после округления σ квантованного шума
   **ровно ноль**. Квантованная рампа растёт прыжками по 1 LSB, и разность превращает
   каждый прыжок в «событие»: **14 287 детекций на 212 реальных.** Критерий, который
   из этого вывелся: **шум/LSB ≳ 0.4**, и он же задаёт разрядность АЦП в обеих ветках
   (16 бит у ЗЧУ, 14 у TIA). См. `../design.md` §7.1.
