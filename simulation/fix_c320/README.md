# fix_c320 — варианты исправления находок 1.1 и 1.3 (2026-09-15)

Источник находок: `review/REVIEW_critic_2026-09-15.md`.

- **1.1** — `C320` (100 нФ на GND) сидит прямо на `PB0` вместе с разделительным `C314` (100 нФ) →
  ёмкостный делитель ×0.5 на входе OPAMP3. Старые деки прятали `C320` за резистором `Rbias 4.65k`,
  которого в схеме нет.
- **1.3** — разделительные цепи `C317`/`R308` и `C314`/(`R310‖R311`) имеют τ ≈ 0.1–0.2 мс, а не «16 Гц»
  из дока → хвосты импульсов, зависящие от загрузки.

## Запуск

```
python simulation/fix_c320/run_spice.py          # деки + LTspice (14 шт., ~45 с) + таблица
simulation\fix_c320\build_dsp.cmd                # firmware/core/dsp.c -> out/dsp_shim.dll (MSVC x64)
python simulation/fix_c320/mc.py --phase-lock    # Монте-Карло, фаза привязана к отсчёту
python simulation/fix_c320/mc.py                 # то же со случайной фазой
```

Всё сгенерированное — в `out/` (игнорируется git).

## Методика

1. **LTspice, транзиент 30 мс** на импульс Cs-137 (0.94 мА, как в `sim_bias_fixed.cir`) — топология по
   нетлисту, TIA поведенческий (+499·I, τ = 2.35 нс). Длинное окно нужно, чтобы увидеть хвосты.
2. **LTspice, `.noise`** до 2 МГц (Найквист при 4 Мвыб/с) — официальная модель ADA4817 + `opamp_g474_noise`.
3. **Монте-Карло**: пуассоновский поток 1/10/30 кимп/с, спектр амплитуд — inverse-CDF Cs-137 из
   `firmware/core/pulsegen.c` (фотопик → дельта, 23.8 % событий), шум с PSD из п. 2, АЦП 12 бит
   @4 Мвыб/с, VREF 2.5 В → **настоящий `dsp.c` прошивки** (порог 25 кодов при полном усилении,
   `min_width=2`, `fit_m=2`). Метрика — FWHM электронной части фотопика (без статистики сцинтиллятора).
4. **Кэмпбелл** — независимая аналитическая оценка флуктуаций базовой линии от хвостов.
5. **Допуски** — Монте-Карло рабочей точки АЦП: смещения ОУ ±3 мВ, резисторы ±1 %, REF35 ±0.05 %,
   PGA ±1 % (допущение: в DS12288 норма на ошибку усиления PGA не найдена).

Контроль модели: вариант `Vdoc` (старая топология) даёт **1159 каналов** — ровно цифра из доков.

## Вывод

1. **1.1 подтверждена симуляцией и обязательна к исправлению**: схема как есть даёт ровно половину
   амплитуды (579 каналов вместо 1159).
2. **Рекомендация — V2**: удалить `C320`, `C317` и `C314` заменить на 1 мкФ X7R. Новых цепей нет,
   трассировка не меняется; лечит 1.1 и 1.3 одновременно (электронное FWHM не зависит от загрузки).
   ⚠ В BOM 1 мкФ есть только в 0805 (`CC0805JKX7R9BB105`), а посадки `C314`/`C317` — 0603:
   либо новый MPN 1 мкФ X7R 0603, либо смена посадки на разведённой плате МК.
   Постоянное напряжение на `C317` ≈ 0.8 В, на `C314` ≈ 1.5 В — DC-bias X7R меняет только τ, не усиление.
3. **V3** равноценна по характеристикам, но требует нового резистора и правки трассировки у `PB0`.
4. **V1** (только удалить `C320`) лечит 1.1, но не 1.3: при 30 кимп/с электронное FWHM ×6.
5. **V4** лучшая по хвостам, но **не рекомендуется** без подстройки на каждой плате: разброс базовой
   линии ±0.2 В съедает запас сверху до 48 мВ.

## Попутные находки

- **Ветка тестового ЦАП `C318`+`R307` (PA4)**: при включённом ЦАП с буфером усиление падает до ×0.887
  и меняется форма импульса (вариант `V1d` в `run_spice.py`). По DS12288 выходное сопротивление ЦАП
  без буфера 9.6…13.8 кОм — тоже нагружает узел. **На время набора спектра ЦАП выключать, PA4 — аналоговый
  вход (Hi-Z).**
- **DSP на боевом импульсе** (FWHM ≈ 2.3 отсчёта @4 Мвыб/с, `fit_m=2`): парабола по 5 точкам занижает пик
  на 12–15 % и даёт фазовый разброс σ ≈ 3 % (FWHM ≈ 7.4 %, сопоставимо с NaI) — при случайной фазе прихода
  (`mc.py` без флага). К находке 5.1 ревью: алгоритм оценки амплитуды нужно переработать до этапа 3.

## Ограничения

- Модель ОУ G474 не ограничена рейлами — клиппинг оценивается по запасам, а не моделируется.
- TIA в транзиенте поведенческий; паразитные ёмкости разводки не учтены.
- Ядро отклика обрезано на 30 мс (τ до 1 мс — хвост к этому времени < 10⁻¹²).
- Шум гауссов с PSD из моделей; 1/f шум ОУ G474 модель не содержит.
- Частота АЦП 4 Мвыб/с по ТЗ; текущая прошивка Nucleo работает на 2.83 Мвыб/с.
