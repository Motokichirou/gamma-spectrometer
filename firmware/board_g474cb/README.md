# board_g474cb — заготовка этапа 3 (боевая плата МК, STM32G474CBT6)

Проекта CubeIDE под боевую плату ещё нет. Здесь лежат готовые куски, которые в него войдут.
Всё сделано, пока платы на заводе (2026-10-14).

| файл | что |
|---|---|
| `STM32G474CBTX_FLASH.ld` | линкер: флеш **128K**, ОЗУ 128K (у `gamma_stage1` 512K — это Nucleo-G474RE) |
| `board_vref.c/.h` | опора АЦП: внутренний **VREFBUF 2.5 В** (пока нет U301) или внешний REF35250 по `-DBOARD_VREF_EXTERNAL` |

`cal_store.c` общий с этапом 1 (`../gamma_stage1/Core/Src/cal_store.c`), правка от 2026-10-14
работает на обеих платах.

## Первое включение платы — по порядку

1. **Проверить кристалл по SWD** (подключение — проводами к выводам LQFP-48: SWDIO 37, SWCLK 38,
   NRST 7). STM32CubeProgrammer при подключении показывает:
   - DEV_ID `0x469` (G47x/G48x);
   - объём флеш `0x1FFF75E0` = `0x0080` (128 КБ);
   - корпус `0x1FFF7500` = `0x0B` (LQFP48).
2. **Опциональные байты — до записи прошивки, на чистом кристалле:**
   ```
   STM32_Programmer_CLI -c port=SWD -ob nSWBOOT0=0 nBOOT0=1 DBANK=0
   ```
   - `nSWBOOT0=0 nBOOT0=1` — висящий вывод BOOT0 (PB8, вывод 45) больше не уводит в загрузчик
     (`CLAUDE.md`, раздел BOOT0);
   - **`DBANK=0`** — один банк, страница 4 КБ. Без этого **калибровка не работает**: у 128 КБ
     в двухбанковом режиме адрес второго банка в `RM0440` (Табл. 7: `0x0804 0000`) и в HAL
     (`FLASH_BASE + FLASH_SIZE/2` = `0x0801 0000`) расходятся. `cal_store.c` в этом случае
     отказывается писать и отвечает `CAL: none`, а не пишет наугад;
   - ⛔ `BOOT_LOCK` не трогать.
   - Проверка: `STM32_Programmer_CLI -c port=SWD -ob displ` → `DBANK : 0x0`, `nSWBOOT0 : 0x0`.
   - *Если интересно, кто прав про второй банк:* при `DBANK=1` прочитать по SWD `0x08010000`
     и `0x08040000` — где окажется отображение, там и банк. Но для работы прибора это не нужно.
3. **Прошить** с линкером `STM32G474CBTX_FLASH.ld`.

## Порядок инициализации в `main()` этапа 3

```c
HAL_Init();
SystemClock_Config();
board_vref_init();                 /* ДО калибровки АЦП: VREF+ должен уже стоять */
/* ... OPAMP1/2/3, ADC1: HAL_ADCEx_Calibration_Start() ... */
/* замер VREFINT (ADC1, канал VREFINT, выборка ≥ 4 мкс) → board_vref_check(raw) */
dsp_init(&dsp, +1, thr, ...);      /* полярность «вверх» от базы 0.41 В */
dsp_set_template(&dsp, &dsp_template[0][0], DSP_TPL_NPH, DSP_TPL_NS,
                 DSP_TPL_IPK, DSP_TPL_Q);   /* эталон формы боевого тракта, dsp_template.h */
```

⚠ Таблица `dsp_template.h` снята с модели тракта (`simulation/fix_c320/`). После первого
спектра заменить на эталон с реального тракта (усреднение ~10 000 импульсов).

## Когда приедет REF35250

1. Впаять U301.
2. Пересобрать с `-DBOARD_VREF_EXTERNAL`: VREFBUF уходит в высокоимпедансное состояние.
3. ⛔ Не наоборот: прошивка с включённым VREFBUF на плате с U301 — два источника на одном узле.
